# VDTOS Implementation Plan

> **For agentic workers:** Implement this plan task-by-task, in order. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `out/vdtos-amd64.hybrid.iso`: Debian 13 + XFCE desktop with a kernel.org longterm kernel, tuned for i3 gen2 / 8GB RAM.

**Architecture:** Bash scripts fetch + verify + build the kernel as a `.deb`; live-build assembles a live/installer ISO from Debian trixie with that `.deb`; a QEMU smoke test boots the ISO and checks RAM and boot time reported over serial.

**Tech Stack:** bash, GNU make, kernel `bindeb-pkg`, live-build, QEMU, xorriso, jq, gpg, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-27-vdtos-design.md`

## Global Constraints
- Build host: GitHub Actions only (no local virtualization). `.github/workflows/build.yml` already exists on `main`; do not edit it. It calls exactly: `bash tests/run.sh` (debian:trixie, as root), `make kernel` and `make iso` (debian:trixie docker, as root — no `sudo` anywhere), `bash tests/smoke.sh` (Ubuntu host with `/dev/kvm`, ISO at `out/vdtos-amd64.hybrid.iso`, must write `out/serial.log`).
- "Run X → expect Y" steps that need Linux: push the branch and read that job on the Actions tab. Unit tests may also run locally in Git Bash if `jq`, `gpg`, `xz` exist.
- Every script starts with `#!/usr/bin/env bash` and `set -euo pipefail`; all text files LF line endings.
- Scripts expose testable functions and only run `main "$@"` when executed directly: `[[ "${BASH_SOURCE[0]}" == "$0" ]] && main "$@"`.
- Kernel: latest `moniker == "longterm"` from `https://www.kernel.org/releases.json`; `CONFIG_LOCALVERSION="-vdtos"`.
- Boot params always include `preempt=full`.
- Thresholds: idle RAM used < 700 MB; `graphical.target` < 30 s (enforced only with `/dev/kvm`).
- Test runner: `tests/run.sh` runs every `tests/test_*.sh`; helpers in `tests/lib.sh`.

## Review Focus
1. `systemd-analyze` prints `1min 4.512s` or `850ms`, not just `8.2s` → parser must return seconds as a number (Task 3 test).
2. `releases.json` lists several longterm (e.g. `6.6.120`, `6.12.9`) → pick by version sort, not string sort (Task 1 test).
3. Tampered tarball or missing `.sign` → nonzero exit and nothing extracted (Task 1 test).
4. Boot hangs and `VDTOS-MEM` never appears in serial log → FAIL with message, never PASS (Task 4 test).
5. Windows checkout converts scripts to CRLF → `.gitattributes` forces LF (Task 1 check).
